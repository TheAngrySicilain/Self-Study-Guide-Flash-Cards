HTML: Give the page meaning.

HTML is the structure and meaning of a page. Good markup helps browsers, users, and assistive technology understand the interface.

Lesson 1 of 8

Document anatomy

Every HTML file follows the same skeleton, and each part of that skeleton exists for a reason. Before you write a single visible word, the browser needs to know what kind of document it is looking at, what language it is written in, how to read its characters, and what metadata describes it. Getting this skeleton right is what makes everything else — styling, scripting, accessibility, search rankings — work correctly.

The doctype and the root element

<!DOCTYPE html> is not an HTML tag; it is an instruction to the browser to render the page in modern "standards mode" instead of a legacy quirks mode that mimics old, inconsistent browser behavior. It must be the very first line of the file.

The <html> element is the root of the whole document and should always carry a lang attribute, such as lang="en". This single attribute tells screen readers which pronunciation rules to use and tells browsers which language to offer for translation. Leaving it out is one of the most common accessibility mistakes.

Inside the head

The <head> holds metadata: information about the page rather than content on the page. Four elements appear in almost every head: a character-set declaration, a viewport tag, a title, and a stylesheet link.

<!DOCTYPE html> <html lang="en"> <head> <meta charset="UTF-8"> <meta name="viewport" content="width=device-width, initial-scale=1"> <title>My Page</title> <link rel="stylesheet" href="styles.css"> </head> <body> <!-- everything visible goes here --> </body> </html>

Why the viewport tag matters

Without <meta name="viewport" content="width=device-width, initial-scale=1">, mobile browsers render the page at a fake desktop width (usually 980px) and then zoom out, making text tiny and layouts unusable on a phone. This one line is what makes a page "mobile friendly" at all.

Common mistake

Forgetting charset="UTF-8" can cause special characters, curly quotes, or emoji to render as garbled symbols, because the browser guesses the wrong text encoding.

Key terms

Doctype
A declaration that tells the browser which rendering mode to use; <!DOCTYPE html> selects modern standards mode.
Root element
The single outermost element of a document; in HTML this is always <html>.
Metadata
Data about the page itself (title, character set, viewport) rather than content shown to visitors.
Standards mode
A browser rendering mode that follows the modern HTML/CSS specifications consistently across browsers.

Key takeaways

  • The doctype must be the first line and triggers standards mode.
  • lang on <html> is required for accessibility and translation.
  • The head describes the page; the body is what a visitor actually sees.
  • The viewport meta tag is what makes a layout responsive on mobile.
Lesson 2 of 8

Semantic HTML and page layout

"Semantic" markup means choosing an element because of what it means, not just how it looks. A <nav> and a <div> can look identical once styled, but only one of them tells a browser, a search engine, and a screen reader "this is the navigation." Semantic HTML is free accessibility and free SEO, and it costs nothing extra to write.

The landmark elements

Modern HTML provides landmark elements that describe the regions of a typical page: <header> for introductory content or a site banner, <nav> for primary navigation links, <main> for the one unique piece of content on the page, <aside> for tangentially related content like a sidebar, and <footer> for closing information. Screen reader users can jump directly between these landmarks with a single keystroke instead of listening to the entire page read aloud.

Article and section

<article> wraps a piece of content that would make sense on its own if syndicated elsewhere, like a blog post or a product card. <section> groups related content under an implicit or explicit heading, such as a "Reviews" section of a product page. When neither meaning applies — you just need a styling hook — reach for a plain <div> or, for inline text, a <span>.

Div soup
<div class="header">...</div> <div class="nav">...</div> <div class="content">...</div> <div class="footer">...</div>
Semantic
<header>...</header> <nav>...</nav> <main>...</main> <footer>...</footer>

Common mistake

Using more than one <main> per page, or nesting <main> inside another landmark. There should be exactly one <main>, holding the content unique to that page.

Key terms

Semantic HTML
Markup chosen for the meaning of the content, not its default appearance.
Landmark
A structural region (header, nav, main, aside, footer) that assistive technology can navigate directly to.
Accessibility (a11y)
Designing so people using screen readers, keyboards, or other assistive tools can use the page.

Key takeaways

  • Choose elements for meaning, not appearance.
  • Landmarks let assistive technology users navigate by region.
  • article stands alone; section groups related content within a page.
  • Reach for div/span only when no semantic element fits.
Lesson 3 of 8

Text content, headings, and lists

Text is the most common content on the web, and HTML gives it structure through a heading hierarchy, paragraphs, inline emphasis, and lists. Getting the hierarchy right creates a page outline that both sighted users skimming the page and screen reader users navigating by heading can follow.

Heading hierarchy

Headings run from <h1> (most important) to <h6> (least important). A page should have exactly one <h1> describing its main topic, and heading levels should not skip — an <h2> should not jump straight to an <h4>. Screen reader users frequently pull up a list of headings to jump around a page, so a broken hierarchy breaks their navigation, not just the visual design.

Inline text and lists

<strong> marks text of strong importance (usually bold); <em> marks stress emphasis (usually italic); both carry semantic weight that a plain <b> or <i> does not. For lists, use <ul> for an unordered set, <ol> when order matters and items should be numbered automatically, and <dl> to pair a term with its description.

<h1>Recipe: Sourdough Bread</h1> <h2>Ingredients</h2> <ul> <li>500g flour</li> <li>350g water</li> </ul> <h2>Steps</h2> <ol> <li>Mix flour and water.</li> <li>Rest for 30 minutes.</li> </ol>

Character entities

Some characters have special meaning in HTML and must be escaped: &lt; for <, &gt; for >, &amp; for &, and &nbsp; for a non-breaking space.

Key terms

Heading hierarchy
The nested order of h1-h6 that forms a page's outline.
Inline element
An element that flows within a line of text, such as strong, em, or a.
Character entity
A reserved code like &amp; used to display a character that would otherwise be parsed as markup.

Key takeaways

  • One h1 per page; never skip heading levels.
  • strong and em carry meaning, not just style.
  • Pick ul, ol, or dl based on what the list actually represents.
Lesson 4 of 8

Links, images, and media

Links and media are what make HTML hypertext instead of a plain document format. Getting their attributes right affects security, performance, and whether users with disabilities can actually perceive your content.

Anchor attributes

An <a> element's href can point to an absolute URL, a relative path, an in-page anchor like #section, an email address via mailto:, or a phone number via tel:. Opening a link in a new tab with target="_blank" should always be paired with rel="noopener noreferrer", because otherwise the new page can access and manipulate the original tab through window.opener, a real security risk.

Writing good alt text

Every informative <img> needs an alt attribute describing what the image conveys, not just what it depicts. A purely decorative image should use alt="" so screen readers skip it entirely instead of announcing a distracting filename. Always set explicit width and height attributes so the browser can reserve space before the image loads, preventing the rest of the page from jumping around (layout shift).

<img src="chart.png" alt="Sales grew 40% from Q1 to Q2" width="600" height="300"> <a href="/report.pdf" download>Download report</a> <a href="https://example.com" target="_blank" rel="noopener noreferrer">External site</a>

Responsive and accessible media

<picture> with multiple <source> elements lets the browser choose the best image format or size for the current screen. <video> and <audio> both accept several <source> children for format fallback, and a <track> element inside <video> supplies captions for viewers who are deaf or watching with the sound off.

<video controls> <source src="lesson.mp4" type="video/mp4"> <track kind="captions" src="captions.vtt" srclang="en"> </video>

Common mistake

alt="image" or alt="photo123.jpg" tells a screen reader user nothing useful. Describe the content or purpose of the image instead.

Key terms

Alt text
A text alternative for an image, announced by screen readers and shown if the image fails to load.
Layout shift
Unwanted movement of page content, often caused by images loading without reserved space.
rel="noopener"
An anchor attribute that stops a new tab from accessing the page that opened it.

Key takeaways

  • Pair target="_blank" with rel="noopener noreferrer".
  • Write alt text that describes meaning, and use alt="" for decoration.
  • Set image width/height to prevent layout shift.
  • track elements provide captions for video.
Lesson 5 of 8

Forms in depth

Forms are how users send data back to a server, and they are one of the most accessibility-sensitive parts of HTML because they require precise input from people who may be using a keyboard, a screen reader, or voice control.

Labels and inputs

Every input needs an associated <label>. The most reliable way is matching the label's for attribute to the input's id; this also enlarges the clickable/tappable target to include the label text, which sighted users benefit from too.

Choosing the right input type

The type attribute changes both validation and the on-screen keyboard shown on mobile devices. email, tel, number, date, and range all trigger specialized input UI without any JavaScript.

Validation and grouping

required, pattern, minlength/maxlength, and min/max let the browser block bad submissions before your code runs. <fieldset> with a <legend> groups related fields — like a shipping address — and announces that group's purpose to assistive technology.

<form action="/signup" method="post"> <fieldset> <legend>Account details</legend> <label for="email">Email</label> <input id="email" name="email" type="email" required> <label for="age">Age</label> <input id="age" name="age" type="number" min="13" max="120" required> </fieldset> <button type="submit">Create account</button> </form>

Accessible error messages

Connect an error message to its field with aria-describedby so a screen reader announces the error immediately after reading the field, instead of leaving the user to discover it separately.

Key terms

Form control
Any input, select, or textarea that collects user data.
Client-side validation
Checks the browser performs before submission, using attributes like required and pattern.
fieldset/legend
A pair of elements that group related form fields under a shared, announced name.

Key takeaways

  • Every input needs a linked label.
  • The right type gives free validation and the correct mobile keyboard.
  • fieldset/legend group and name related fields.
  • Native validation attributes reduce the JavaScript you need to write.
Lesson 6 of 8

Tables for tabular data

Tables were once misused for entire page layouts before CSS matured; today they should be reserved strictly for data that actually has rows and columns, like a schedule, a price list, or a comparison chart.

Table structure

<thead>, <tbody>, and <tfoot> group a table's header, body, and summary rows. <th> marks a header cell and <td> marks a data cell. A <caption> as the table's first child gives it an accessible name, similar to an image's alt text.

Making tables accessible

The scope attribute on a <th> declares whether that header applies to its column or its row, which lets a screen reader announce the right header as a user moves through the data cells.

<table> <caption>Quarterly sales by region</caption> <thead> <tr><th scope="col">Region</th><th scope="col">Q1</th></tr> </thead> <tbody> <tr><th scope="row">West</th><td>$12,400</td></tr> </tbody> </table>

Common mistake

Using a table purely to arrange unrelated content side by side. That is a job for CSS Flexbox or Grid, covered in the next module.

Key terms

Tabular data
Data naturally organized into rows and columns, the only appropriate use for a table.
scope
A th attribute declaring whether a header describes its column or its row.
Caption
An accessible, visible name for a table, similar in purpose to an image's alt text.

Key takeaways

  • Tables are for tabular data, never for page layout.
  • scope ties a header to its column or row for screen readers.
  • caption gives the whole table an accessible name.
Lesson 7 of 8

Accessibility fundamentals

Accessibility means a page can be used by people with visual, motor, auditory, or cognitive disabilities, typically using a screen reader, keyboard-only navigation, or voice control. Semantic HTML, covered throughout this module, is the foundation; ARIA and focus management fill the remaining gaps.

The first rule of ARIA

The first rule of ARIA is: do not use ARIA if a native HTML element or attribute already provides the behavior or semantics you need. A native <button> is already keyboard-operable and announced correctly; recreating it with a styled <div role="button"> means you must also manually add keyboard support, focus styles, and state management that the browser gave you for free.

Keyboard navigation and focus

Every interactive element must be reachable and operable using only the Tab key and Enter/Space, because many users cannot use a mouse. A visible focus outline is not optional decoration; removing it with outline: none and not replacing it with something equally visible strands keyboard users. A "skip to main content" link as the very first focusable element lets keyboard users bypass repeated navigation on every page.

<a class="skip-link" href="#main">Skip to main content</a> <nav>...</nav> <main id="main">...</main>

Color and contrast

Text needs sufficient contrast against its background to be legible for users with low vision or color blindness, and color should never be the only way information is conveyed — pair a red error color with an icon or the word "Error" as well.

Key terms

ARIA
Accessible Rich Internet Applications; a set of attributes that describe roles and states HTML cannot express natively.
Focus management
Controlling which element currently receives keyboard input, and making that element visibly obvious.
Skip link
A hidden-until-focused link letting keyboard users jump past repeated navigation.

Key takeaways

  • Prefer native elements over ARIA re-implementations.
  • Never remove focus outlines without an equally visible replacement.
  • Add a skip link as the first focusable element.
  • Never rely on color alone to convey meaning.
Lesson 8 of 8

Debugging and validating HTML

Browsers are extremely forgiving of malformed HTML: an unclosed tag or a missing quote usually still renders something, which can hide real bugs until they surface unpredictably in a different browser or after a small edit elsewhere on the page.

Inspecting the real DOM

Open DevTools' Elements panel to see the DOM the browser actually built, which can differ from your source code once the browser has "fixed" invalid nesting. If an element you expect to see is missing or duplicated, this is the first place to look.

Common structural bugs

  • An unclosed tag that swallows the rest of the page inside it.
  • Block-level elements like div or p nested inside inline elements like span or a, which some browsers silently rearrange.
  • Duplicate id values: an id must be unique per page, and duplicates break both CSS selectors and label for associations.
  • A label for that no longer matches its input's id after a rename.

Validate before you ship

Running a page through an HTML validator surfaces structural errors that the browser silently repaired, before they cause a real bug for a real user.

Key terms

DOM
Document Object Model; the browser's live, in-memory tree representation of the parsed page.
Validator
A tool that checks markup against the HTML specification and reports structural errors.
Duplicate ID
Two elements sharing one id value, which breaks CSS selectors and form label associations.

Key takeaways

  • Browsers silently repair bad HTML, which can hide bugs.
  • Use DevTools' Elements panel to see the real, parsed DOM.
  • Duplicate id values are a frequent, hard-to-spot bug.

The box model

Every single element on a page is a rectangular box, and CSS lays those boxes out one by one. Before you can control layout with Flexbox or Grid, you need to understand how one box's own size is calculated, because that calculation is the foundation everything else builds on.

Four layers, from the inside out

Every box has four layers. Content is the actual text or image. Padding is transparent space inside the border, pushing the border away from the content. Border is a visible or invisible line around the padding. Margin is transparent space outside the border, pushing other elements away.

margin
border
padding
content: 240px

content-box: padding and border add to the declared width.

Two competing box-sizing models

By default (box-sizing: content-box), the width you declare applies only to the content layer; padding and border are added on top, so the final rendered box is always larger than the number you typed. box-sizing: border-box instead makes width include the padding and border, so the box you declare is the box you get. This is why nearly every modern CSS reset starts with * { box-sizing: border-box; }.

.card { width: 300px; padding: 20px; border: 2px solid; box-sizing: border-box; /* rendered width stays 300px */ }

Common mistake

Setting a fixed width on a content-box element and then adding padding, and being surprised when it overflows its parent. Switch to border-box first when this happens.

Key terms

Box model
The rectangular content/padding/border/margin structure the browser uses to size and space every element.
box-sizing
The property that chooses whether width/height include padding and border (border-box) or not (content-box).
Margin collapse
The behavior where two vertical margins between sibling elements combine into a single margin instead of adding together.

Key takeaways

  • Every element is a box with content, padding, border, and margin layers.
  • border-box keeps padding and border inside the declared width.
  • Most resets set border-box globally to avoid surprise overflow.
Lesson 2 of 8

Selectors and the cascade

CSS stands for Cascading Style Sheets, and the "cascading" part is the set of rules the browser uses to decide which declaration wins when multiple rules target the same element. Understanding the cascade turns "why isn't my CSS working" into a predictable, debuggable process.

Selector types

A type selector like p targets every element of that tag. A class selector like .card targets every element with that class, and is the most common building block for reusable styles. An ID selector like #header targets a single, unique element. Combinators like a space (descendant), > (direct child), and , (grouping multiple selectors) let you target more precisely.

Specificity

When two rules target the same element, the browser calculates each selector's specificity: roughly, ID selectors outweigh class selectors, which outweigh type selectors. The more specific selector wins, regardless of the order the rules appear in the file. Only when specificity ties does source order decide, with the later rule winning.

#nav .link { color: navy; } /* id + class beats a class alone */ .link { color: gray; } p { color: black; } /* type selectors have the lowest weight */

Common mistake

Reaching for !important to force a rule to win. It breaks the normal cascade and makes future overrides much harder; fix the selector's specificity instead.

Key terms

Cascade
The algorithm the browser uses to resolve conflicting rules, based on origin, specificity, and source order.
Specificity
A weighting system that scores a selector by how precisely it targets an element.
Combinator
A symbol (space, >, +, ~) that describes the relationship between two selectors.

Key takeaways

  • Class selectors are the standard building block for reusable styles.
  • Higher specificity wins regardless of source order.
  • Avoid !important; fix the selector instead.
Lesson 3 of 8

Flexbox, one-dimensional layout

Flexbox arranges a group of items along a single line, either a row or a column, and excels at distributing space and aligning items within that one dimension.

The two axes

Setting display: flex on a parent creates a main axis, which follows flex-direction (row by default), and a cross axis running perpendicular to it. justify-content aligns items along the main axis; align-items aligns them along the cross axis.

.row { display: flex; flex-direction: row; justify-content: space-between; align-items: center; gap: 12px; }

Letting items grow and shrink

flex-grow lets an item expand to fill leftover space, flex-shrink lets it shrink when space is tight, and flex-basis sets its starting size before growing or shrinking. The shorthand flex: 1 means "grow and shrink freely, starting from zero."

Why it matters

gap replaces the old trick of adding margin to every child except the last one, and works identically in Flexbox and Grid.

Key terms

Main axis
The primary direction items are laid out along, set by flex-direction.
Cross axis
The axis perpendicular to the main axis.
flex shorthand
Combines flex-grow, flex-shrink, and flex-basis into one declaration.

Key takeaways

  • Flexbox lays out items along one axis at a time.
  • justify-content is main-axis; align-items is cross-axis.
  • gap spaces items without extra margin hacks.

CSS Grid, two-dimensional layout

Where Flexbox handles one dimension at a time, Grid lets you define rows and columns together and place items anywhere in that structure, which suits whole-page layouts far better than nested Flexbox containers.

Defining the grid

grid-template-columns and grid-template-rows describe the size of each track. The fr unit divides remaining space proportionally, so repeat(4, 1fr) creates four equal-width columns that share all available space.

Named template areas

grid-template-areas lets you sketch a layout as ASCII art and assign each child to a named region, which makes complex page layouts easy to read at a glance.

.page { display: grid; grid-template-columns: 200px 1fr; grid-template-areas: "sidebar header" "sidebar main"; } .sidebar { grid-area: sidebar; }

Key terms

Track
A single row or column in a grid.
fr unit
A fraction of the remaining free space in a grid container.
Grid area
A named region of the grid assigned via grid-template-areas and grid-area.

Key takeaways

  • Grid controls rows and columns together; Flexbox controls one axis.
  • The fr unit distributes remaining space proportionally.
  • grid-template-areas makes page layout easy to visualize.
Lesson 5 of 8

Positioning and stacking

The position property changes how an element participates in normal document flow, and is what makes overlays, tooltips, sticky headers, and badges possible.

The five position values

  • static: the default; offsets like top/left are ignored.
  • relative: offsets move it visually from its normal spot, but it still occupies its original space.
  • absolute: removed from flow entirely, positioned against the nearest ancestor that is not static.
  • fixed: positioned against the viewport itself, ignoring scrolling.
  • sticky: behaves like relative until a scroll threshold, then sticks like fixed.
.card { position: relative; } .badge { position: absolute; top: 8px; right: 8px; }

Stacking order

When positioned elements overlap, z-index decides which one renders on top, but only among elements that already have a position other than static. A very large z-index used to "just fix it" is a sign of an unresolved stacking-context problem.

Common mistake

Forgetting to set position: relative on the intended parent, so an absolute child positions itself against the whole page instead.

Key terms

Positioned element
Any element whose position is not static.
Containing block
The ancestor an absolute element is positioned relative to.
Stacking context
A conceptual layer that groups how z-index is compared among a set of elements.

Key takeaways

  • absolute positions against the nearest non-static ancestor.
  • sticky combines relative and fixed behavior around a scroll threshold.
  • A huge z-index usually hides a real stacking-context bug.
Lesson 6 of 8

Responsive design

Responsive design means one layout adapts to many screen sizes, from a narrow phone to a wide desktop monitor, instead of maintaining separate pages for each.

Media queries

A media query applies a block of CSS only when a condition, most often a minimum viewport width, is met. Writing "mobile-first" means the base styles target small screens, and min-width media queries progressively add complexity for larger screens.

.layout { display: block; } @media (min-width: 768px) { .layout { display: grid; grid-template-columns: 200px 1fr; } }

Fluid sizing

Prefer max-width with width: 100% over a fixed pixel width, so content shrinks gracefully on narrow screens instead of causing horizontal scrolling. Images should carry max-width: 100% so they never overflow their container.

Test at real widths

Check layouts at roughly 320px (small phone), 768px (tablet), and 1440px (desktop) rather than only your own monitor's width.

Key terms

Media query
A conditional CSS block that applies only when the viewport matches given criteria.
Mobile-first
Writing base styles for small screens first, then adding complexity with min-width queries.
Breakpoint
A viewport width at which the layout changes meaningfully.

Key takeaways

  • Media queries apply styles conditionally based on viewport size.
  • Mobile-first means writing small-screen styles first.
  • Test at multiple real widths, not just your own monitor.
Lesson 7 of 8

Custom properties and units

CSS custom properties (informally called CSS variables) let you name a reusable value once and reference it everywhere, which is the foundation of consistent, themeable design systems.

Declaring and reading a custom property

A custom property is declared with two leading dashes, usually on :root so it is available everywhere, and read with the var() function, which accepts an optional fallback value as its second argument.

:root { --brand: #263f5b; --gap: 12px; } .button { background: var(--brand); } .stack { gap: var(--gap, 8px); }

Choosing the right unit

rem is relative to the root element's font size and stays predictable no matter how deeply nested an element is, which makes it the standard choice for spacing and type. em is relative to the current element's own font size and compounds when nested, which can surprise you. % is relative to the parent's size, and vh/vw are relative to the viewport's height and width.

Key terms

Custom property
A reusable, named value declared with --name and read with var(--name).
Design token
A named, reusable design decision (a color, spacing value, or font size) often implemented as a custom property.
Root font size
The font size of the html element, which rem units are always relative to.

Key takeaways

  • Custom properties cascade like normal CSS and can be overridden per component.
  • Prefer rem for predictable spacing and type sizing.
  • var() accepts a fallback as its second argument.
Lesson 8 of 8

Transitions, animations, and transforms

Motion, used sparingly, helps users understand what changed and why, turning an abrupt jump into a change they can follow with their eyes.

Transitions

A transition smoothly animates a property between its old and new value whenever that value changes, such as on hover or a class toggle. Declare the property, duration, and easing curve; animate only transform and opacity when possible, since the browser can run those on the compositor without recalculating layout.

.box { transition: transform .6s ease, background .6s ease; } .box.playing { transform: translateX(140px); }

Keyframe animations and transform functions

@keyframes defines multiple steps of an animation, useful for effects a simple two-state transition cannot express, like a continuous spinner. Values, types, and variables

JavaScript has two families of values: primitives, which are copied by value, and objects (including arrays and functions), which are copied by reference. Confusing the two is the single most common source of "my data changed somewhere I didn't expect" bugs.

Primitive types

The primitive types are string, number, boolean, null, undefined, and symbol. Assigning a primitive to a new variable copies its value; the two variables are independent from then on.

Reference types

Objects and arrays are reference types. Assigning one to a new variable copies the reference (the memory address), not the data, so both variables point to the exact same object. Changing a property through either variable is visible through both.

let a = 5; let b = a; b = 10; // a is still 5 const objA = { count: 1 }; const objB = objA; objB.count = 99; // objA.count is now 99 too

Declaring variables

const should be your default: it cannot be reassigned, which makes code easier to reason about. Use let only when a variable must change, such as a loop counter. Avoid var entirely in new code; it has confusing function-scoping and hoisting rules covered in a later lesson.

Common mistake

Using const does not make an object immutable — it only stops reassignment of the variable. const obj = {}; obj.name = 'Ada'; is perfectly legal.

Key terms

Primitive
A value type copied by value: string, number, boolean, null, undefined, or symbol.
Reference type
An object, array, or function; variables hold a reference to it, not the data itself.
Immutability
Treating data as unchangeable, creating a new value instead of modifying the original.

Key takeaways

  • Primitives copy by value; objects and arrays copy by reference.
  • Default to const; use let only when reassigning.
  • const prevents reassignment, not mutation of an object's contents.
Lesson 2 of 8

Operators and control flow

Control flow is how a program decides which code actually runs, and it depends entirely on how JavaScript evaluates truth.

Equality: == versus ===

=== (strict equality) compares value and type with no conversion, and should be your default. == (loose equality) converts one or both sides before comparing, which produces surprising results like 0 == false being true. Always reach for === unless you have a specific reason not to.

Truthy and falsy values

In a boolean context like an if, exactly six values are falsy: false, 0, "", null, undefined, and NaN. Everything else, including "0" and an empty array [], is truthy.

if (user.name) { /* runs unless name is "", null, or undefined */ } for (let i = 0; i < items.length; i++) { /* classic loop */ } for (const item of items) { /* preferred for arrays */ }

Choosing a loop

for...of iterates values and is the standard choice for arrays. for...in iterates an object's enumerable keys and should not be used on arrays. A switch statement reads more clearly than a long if/else if chain when comparing one value against many exact cases.

Key terms

Strict equality (===)
Compares value and type with no implicit conversion.
Truthy/falsy
Whether a value evaluates as true or false in a boolean context.
Short-circuit evaluation
How && and || stop evaluating as soon as the result is determined.

Key takeaways

  • Prefer === over == to avoid implicit type conversion.
  • Only six values are falsy; everything else is truthy.
  • Use for...of for arrays, not for...in.
Lesson 3 of 8

Functions, three ways

A function is a reusable block of logic, and JavaScript gives you three syntaxes for writing one, each with slightly different behavior.

function greet(name) { return `Hi ${name}`; } // declaration, hoisted const greet2 = function(name) { return `Hi ${name}`; }; // expression const greet3 = name => `Hi ${name}`; // arrow, no own 'this'

Hoisting and this

A function declaration is hoisted, meaning it can be called before its line in the file. A function expression is not. Arrow functions do not get their own this; they use whatever this was in the surrounding scope where they were defined, which is exactly why they are the standard choice for callbacks inside class methods and React components.

Default and rest parameters

A parameter can declare a default value used when no argument (or undefined) is passed. A rest parameter, written ...args, gathers any remaining arguments into a real array.

function connect(url, timeout = 5000) { /* timeout defaults to 5000 */ } function sum(...numbers) { return numbers.reduce((a, b) => a + b, 0); }

Key terms

Hoisting
The behavior where function and var declarations are conceptually moved to the top of their scope before code runs.
Higher-order function
A function that takes another function as an argument or returns one.
Default parameter
A parameter value used automatically when no argument is supplied.

Key takeaways

  • Only function declarations are hoisted, not expressions or arrows.
  • Arrow functions inherit this from where they were defined.
  • Rest parameters collect extra arguments into a real array.
Lesson 4 of 8

Arrays, objects, and destructuring

Most real work in JavaScript is transforming lists of data, and a small set of array methods cover the vast majority of cases without ever writing a manual loop.

The core three: map, filter, reduce

map transforms every item and returns a new array of the same length. filter tests every item and returns a new array containing only the ones that pass. reduce folds an entire array down into a single value, such as a total or a lookup object. forEach simply runs a function per item and always returns undefined — never chain off it expecting a result.

const names = users.map(u => u.name); const active = users.filter(u => u.active); const total = orders.reduce((sum, o) => sum + o.price, 0);

Destructuring, spread, and rest

Destructuring pulls values out of an array or object straight into named variables. The spread operator (...) copies items out of an array or object; the same three dots gather extra items into a variable when used in a parameter list or a destructuring pattern, where it is called "rest" instead.

const { name, active } = user; const [first, ...rest] = items; const merged = { ...defaults, ...overrides };

Why this matters

Spread is also the standard way to update state immutably: { ...user, active: true } creates a new object instead of mutating user directly.

Key terms

Immutable update
Creating a new array or object instead of mutating the existing one.
Spread operator
... used to expand an array or object's items into a new one.
Destructuring
Syntax that unpacks array or object values directly into named variables.

Key takeaways

  • map transforms, filter selects, reduce folds to one value.
  • forEach returns undefined; never chain off it.
  • Spread syntax is the standard tool for immutable updates.
Lesson 5 of 8

Closures and scope

A closure is what lets a function remember and keep using variables from the scope it was created in, even after that outer scope has already finished running. This single idea explains private counters, memoized caches, and why event handlers can still see the data they were set up with.

Block versus function scope

let and const are block-scoped: they only exist inside the nearest { }. var is function-scoped and ignores block boundaries entirely, which is one reason it is avoided in modern code.

function makeCounter() { let count = 0; // captured by the closure below return () => ++count; } const next = makeCounter(); next(); next(); // 1, then 2 — count is remembered

A scope leak example

function run() { if (true) { let scoped = 'inside'; var leaked = 'still visible outside the if'; } console.log(leaked); // works — var ignores the block console.log(scoped); // ReferenceError — let respects the block }

Key terms

Closure
A function bundled with references to the variables from its surrounding scope at the time it was created.
Block scope
Visibility limited to the nearest enclosing { }, used by let/const.
Temporal dead zone
The period before a let/const declaration's line runs, where reading it throws an error.

Key takeaways

  • A closure keeps outer variables alive as long as the inner function exists.
  • let/const are block-scoped; var is function-scoped.
  • Closures are how counters and caches keep private state between calls.
Lesson 6 of 8

Asynchronous JavaScript

JavaScript runs on a single thread, so it cannot literally do two things at once; instead, slow operations like network requests are handed off and their results arrive later through callbacks, Promises, or async/await.

From callbacks to Promises

A callback is a function passed in to be called once an operation finishes. Deeply nested callbacks become hard to read ("callback hell"). A Promise represents a future success or failure and can be chained with .then()/.catch() instead of nesting.

async/await

async/await is syntax built on top of Promises that lets asynchronous code read top-to-bottom like synchronous code. await pauses only the current async function until the Promise settles; it does not block the rest of the page.

async function loadUser(id) { try { const res = await fetch(`/api/users/${id}`); if (!res.ok) throw new Error('Request failed'); return await res.json(); } catch (err) { console.error(err); } }

Common mistake

fetch only rejects on a network failure; a 404 or 500 response still resolves normally. Always check response.ok before trusting the body.

Key terms

Event loop
The mechanism that lets JavaScript run pending callbacks after the current code finishes, enabling asynchronous behavior on one thread.
Promise
An object representing the eventual success or failure of an asynchronous operation.
await
Pauses an async function until a Promise settles, without blocking the rest of the program.

Key takeaways

  • JavaScript is single-threaded; async operations hand off and resume later.
  • async/await is Promise syntax that reads top-to-bottom.
  • Always check response.ok; fetch resolves even for error statuses.
Lesson 7 of 8

Error handling and JSON

Real programs fail: a network drops, a user types something unexpected, a server returns bad data. Handling errors deliberately, instead of letting them crash silently, is what separates a robust program from a fragile one.

try/catch/finally

try runs code that might fail. catch handles the error if it does. finally always runs afterward, whether or not an error occurred, which makes it the right place for cleanup like hiding a loading spinner.

try { JSON.parse(badInput); } catch (err) { console.error('Invalid JSON:', err.message); } finally { setLoading(false); }

JSON in and out

JSON (JavaScript Object Notation) is the standard text format for sending structured data over a network. JSON.stringify converts a JavaScript value into a JSON string; JSON.parse converts it back. Both throw an error on malformed input, which is exactly why they belong inside a try/catch.

const body = JSON.stringify({ name: 'Ada' }); const data = JSON.parse(responseText);

Key terms

Exception
An error thrown during execution that interrupts the normal flow unless caught.
JSON
A lightweight, text-based data format used to exchange structured data between systems.
finally
A block that always runs after try/catch, regardless of whether an error occurred.

Key takeaways

  • finally always runs, making it ideal for cleanup.
  • JSON.stringify serializes; JSON.parse deserializes.
  • Both JSON methods can throw, so wrap them in try/catch.
Lesson 8 of 8

The DOM and events

The Document Object Model (DOM) is the browser's live, in-memory tree of the page. Plain JavaScript can read and change that tree directly, which is the foundation that frameworks like React ultimately build on top of.

Selecting and changing elements

const button = document.querySelector('.save-button'); button.textContent = 'Saved!'; button.classList.add('is-active');

Listening for events

addEventListener attaches a handler function that runs when an event, like a click, fires on an element. Events "bubble" upward through ancestor elements by default, which enables event delegation: attaching one listener to a parent instead of one listener per child, useful for lists that change over time.

list.addEventListener('click', event => { if (event.target.matches('.delete-btn')) { event.target.closest('li').remove(); } });

Why it matters

Event delegation means newly added list items automatically work with the existing listener, with no need to attach a new one to every item.

Key terms

DOM
Document Object Model; the browser's live tree representation of the page that JavaScript can read and modify.
Event bubbling
The default behavior where an event fired on an element also fires on its ancestors.
Event delegation
Attaching one listener to a parent element to handle events from many children, including future ones.

Key takeaways

  • The DOM is a live tree that JavaScript can query and mutate directly.
  • Events bubble from the target element up through its ancestors.
  • Event delegation avoids attaching a listener to every individual item.

Components and JSX

React builds an interface out of components: small, reusable functions that each return a description of some UI. Instead of imperatively pushing DOM changes yourself, you describe what the UI should look like for the current data, and React figures out how to update the real page to match.

What JSX actually is

JSX is a syntax extension that lets you write HTML-like markup directly inside JavaScript. It is not a template language; it compiles down to plain function calls that build a tree of objects describing the UI. That is why curly braces { } embed a JavaScript expression, never a statement like if or a for loop.

function Greeting({ name }) { return <h2 className="title">Hello, {name}!</h2>; }

Rules JSX enforces

  • A component must return a single root element; wrap multiple siblings in a <>...</> fragment.
  • Use className instead of class, since class is a reserved JavaScript word.
  • Every element must be closed, including self-closing tags like <img />.

Key terms

Component
A reusable function that accepts props and returns a description of UI.
JSX
A syntax extension that compiles HTML-like markup into JavaScript function calls.
Fragment
An invisible wrapper (<>...</>) used to return multiple elements without adding an extra DOM node.

Key takeaways

  • Components are functions that return UI descriptions, not direct DOM edits.
  • Curly braces hold expressions only, never statements.
  • Fragments group siblings without adding an extra wrapping element.
Lesson 2 of 8

Props and composition

Props (short for properties) are the read-only inputs a parent passes down to a child component. They are how data flows through a React application, always downward.

parent state
↓ props
child UI
↑ callback
state update

Children and composition

The special children prop lets a parent decide what content goes inside a wrapper component, which avoids duplicating layout markup like card borders or modal chrome everywhere they are used.

function Card({ children }) { return <div className="card">{children}</div>; } <Card><p>Any content here</p></Card>

Why it matters

Because data only flows down through props, a bug where the wrong value appears can always be traced by following props upward to whichever component actually owns that state.

Key terms

Props
Read-only values passed from a parent component into a child.
Unidirectional data flow
The React principle that data flows down through props, and requests to change it flow up through callbacks.
Composition
Building complex UI by combining smaller components, often via the children prop.

Key takeaways

  • Props are read-only; a child never changes its own props directly.
  • Data flows down through props; change requests flow up through callbacks.
  • children lets a parent supply arbitrary content to a wrapper.
Lesson 3 of 8

State and useState

State is data a component owns and can change over time, and a state change is exactly what triggers React to re-render. useState is the fundamental hook for adding state to a function component.

const [count, setCount] = useState(0);

Never mutate state directly

Always create a new array or object reference instead of mutating the existing one; React compares references to decide whether to re-render, so mutating in place can silently fail to update the screen.

Functional updates

When the next state depends on the previous state, pass a function to the setter instead of a plain value. This guarantees you are updating from the latest state, even if multiple updates happen in quick succession.

setCount(prev => prev + 1); // safe, always current setCount(count + 1); // can use a stale value

Common mistake

Storing a value in state that could instead be calculated during render from existing props or state. Derived values should never be duplicated into their own state slot.

Key terms

State
Component-owned data that can change and triggers a re-render when it does.
Functional update
Passing a function to a state setter so it always reads the latest state value.
Derived state
A value calculated from existing props or state during render, instead of stored separately.

Key takeaways

  • Never mutate state directly; always create a new reference.
  • Use a functional update when the next state depends on the previous one.
  • Calculate derived values during render instead of storing duplicates.
Lesson 4 of 8

useEffect and side effects

Rendering should be a pure calculation of UI from props and state. Anything that reaches outside that calculation — fetching data, subscribing to an event, manually touching the DOM — is a side effect, and belongs inside useEffect.

The dependency array

The array passed as useEffect's second argument controls how often it runs. An empty array [] means "run once, after the first render." Listing a value means "re-run whenever that value changes." Omitting the array entirely means "run after every render," which is rarely what you want.

useEffect(() => { const id = setInterval(tick, 1000); return () => clearInterval(id); // cleanup, runs before the next effect or on unmount }, []);

Common mistake

Reading a prop or state value inside useEffect without listing it in the dependency array. The effect then runs with a stale, outdated value instead of the current one.

Key terms

Side effect
Any operation that reaches outside the pure render calculation, such as a network request.
Dependency array
The list of values a useEffect depends on, controlling when it re-runs.
Cleanup function
The function an effect can return, run before the next effect or on unmount, to cancel subscriptions or timers.

Key takeaways

  • Side effects belong in useEffect, not directly in render.
  • The dependency array controls how often the effect re-runs.
  • Missing dependencies are a leading cause of stale-data bugs.
Lesson 5 of 8

Lists, keys, and conditional rendering

Rendering a dynamic list is one of the most common React patterns, and getting the key prop right is what lets React correctly track which item is which between renders.

{items.length === 0 ? <p>No items yet.</p> : items.map(item => <Row key={item.id} item={item} />)}

Why keys must be stable

A key must be a stable identifier drawn from the actual data, such as a database id, never the array index. If the list can be reordered, filtered, or have items removed, an index-based key can end up pointing at the wrong item after a re-render, causing input state or animations to attach to the wrong row.

Conditional rendering patterns

A ternary handles a simple either/or choice inline. && is a compact way to render something only when a condition is true. For more complex branching, an early return at the top of the component keeps the main render logic readable.

Key terms

Key
A stable, unique identifier React uses to match list items correctly between renders.
Reconciliation
React's process of comparing the new render output to the previous one to decide what actually needs to change in the DOM.

Key takeaways

  • Keys must be stable and drawn from data, never the array index.
  • Bad keys cause state and focus to attach to the wrong list item.
  • Prefer an early return for complex conditional branching.
Lesson 6 of 8

Forms and controlled components

A controlled input's displayed value always comes from React state, and every keystroke updates that state through an onChange handler, keeping the UI and the underlying data perfectly in sync.

const [name, setName] = useState(''); <input value={name} onChange={e => setName(e.target.value)} />

Submitting without a full page reload

Calling event.preventDefault() inside a submit handler stops the browser's default full-page navigation, letting you read the already-current values from state instead of querying the DOM directly.

function handleSubmit(e) { e.preventDefault(); onAdd({ id: crypto.randomUUID(), name, active: true }); setName(''); }

Key terms

Controlled component
A form element whose value is driven entirely by React state.
onChange
The event handler that fires on every keystroke or value change in a controlled input.

Key takeaways

  • A controlled input's value always comes from state.
  • preventDefault() stops the default full-page form submission.
  • Reset form state after a successful submit.

Next.js Server and Client Components

In the Next.js App Router, every component is a Server Component by default: it renders on the server and sends only the resulting HTML to the browser, with no extra JavaScript shipped for it.

Why the boundary exists

Server Components cannot use browser-only APIs, event handlers, or hooks like useState, because they never run in the browser at all. Adding "use client" at the very top of a file opts that component (and everything it imports) into the client bundle, enabling interactivity.

"use client"; import { useState } from "react"; export default function Counter() { const [count, setCount] = useState(0); return <button onClick={() => setCount(c => c + 1)}>{count}</button>; }

Keep the boundary small

Put "use client" on the smallest, most specific component that actually needs interactivity, rather than at the top of a whole page. This keeps as much of the tree as possible rendered on the server, which ships less JavaScript to the browser.

Hydration

Hydration is the process of attaching React's client-side behavior — event listeners, state — to HTML that was already rendered on the server, making previously static markup interactive.

Key terms

Server Component
A component rendered on the server; the App Router default, cannot use client-only hooks or browser APIs.
Client Component
A component marked with "use client" that can use state, effects, and event handlers.
Hydration
Attaching client-side React behavior to HTML that was already rendered on the server.

Key takeaways

  • Components are Server Components by default in the App Router.
  • "use client" opts a component into the interactive client bundle.
  • Keep the client boundary as small and specific as possible.

Example component hierarchy

App ├─ TaskBoard (owns tasks state) │ ├─ TaskForm (add task) │ ├─ TaskList │ │ └─ TaskItem × N (key = task.id) │ └─ TaskFilters (derived counts)

Where each piece lives

State lives as high as the components that need it. Props flow down to TaskItem; the toggle and delete callbacks flow back up to TaskBoard, which is the only place state actually changes.

Glossary and review system.

Reference

HTML

Element: a complete HTML unit. Attribute: extra configuration on an opening tag. Semantic HTML: markup that communicates purpose.

Void element: an element with no closing tag, such as br or img.

CSS and JavaScript

Computed style: the final value the browser applies. Reference type: an array or object whose variable points to a value.

Promise: a future success or failure. Immutable update: a new array or object instead of direct mutation.

React and Next.js

Props: read-only values from a parent. State: changing component-owned data. Key: stable identity for a list item.

Hydration: attaching client behavior to server-rendered HTML.

Module 01

HTML: Give the page meaning.

HTML is the structure and meaning of a page. Good markup helps browsers, users, and assistive technology understand the interface.

Build the skeleton

Every HTML page begins with a document declaration, a root element, metadata, and visible content.

<!DOCTYPE html> <html lang="en"> <head> <meta charset="UTF-8"> <title>My Page</title> </head> <body>Content</body> </html>

Knowledge check

Which section contains metadata, the page title, and the external stylesheet link?

Module 02

CSS: Make space predictable.

The box model explains size. Flexbox explains alignment. Responsive constraints keep the page usable across screens.

Flexbox axes

justify-content works along the main axis. align-items works along the cross axis. Change flex-direction to change the main axis.

display: flex; flex-direction: row; justify-content: center; align-items: center;

Knowledge check

Which property includes padding and borders inside the declared width?

Module 04

React: Make state and data flow visible.

React becomes predictable when data flows down through props and change requests flow up through focused callbacks.

Data flow diagram

↓ props

↑ callback
state update
setCount(prev => prev + 1)

State rules

  • Never mutate state directly.
  • Use a new array or object reference.
  • Use functional updates when next state depends on previous state.
  • Calculate derived values instead of storing duplicates.
  • Give mapped list items stable unique keys.

Knowledge check

Which update avoids a stale state bug when the next count depends on the previous count?

Module 05

Debugging: Follow the evidence.

Do not guess at a broken interface. Use the Console, Network tab, and the smallest relevant code snippet to make the failure specific.

5 / 6

1 · Console

Read the exact error, file name, and line number.

2 · Network

Inspect URL, method, status, payload, and response.

3 · Explain

Give AI the failing function and exact error, not the whole project.

Review an AI snippet

items.forEach(item => item.name) setItems(items) items.map((item, index) => <Row key={index} item={item} />)

Identify at least three issues. Think about return values, mutation, and stable keys.

Module 06

Capstone: Build and teach back.

Combine the month into a responsive task board. The goal is not just working code; it is a clear explanation of the data flow and your debugging decisions.

6 / 6

Build sequence

  1. Sketch the component hierarchy.
  2. Define the task object shape.
  3. Add immutable add, toggle, and delete actions.
  4. Derive filtered counts during render.
  5. Use stable IDs for list keys.
  6. Test responsive layout and all visible states.

Completion checklist

  • Semantic page structure
  • Responsive two-column layout
  • Immutable data demo
  • React task board
  • Reviewed and explained

Teach-back prompt

Record a five-minute explanation: Where does data enter? Where does it change? Which components receive it? How would you diagnose a failed request or stale UI?
